# report-digests

[Appendix A](../reference/report-digests.md) lists this Worker's routes, crons, queues, storage and bindings.

Deployed as `svbc-report-digests` (production) and `svbc-report-digests-sandbox` (sandbox). It has
no custom hostname; its operator route is on
`https://svbc-report-digests.svbc-account.workers.dev`. It reads Monday through the `monday-auth`
broker's `ReadOnlyToken` entrypoint (the Read-only OAuth app) and sends email through a Cloudflare
`send_email` binding, from `noreply@mail.bikesiliconvalley.org`.

## What it does

It emails staff scheduled digests of Monday board views: gifts with no donor, upcoming membership
renewals, recent gifts of $400 and up, the fiscal year by gift size, and last week's gifts. They
replace the Salesforce report subscriptions; Monday's own scheduled dashboard email needs the
Enterprise plan. If it stops, staff stop getting these weekly and twice-monthly emails. The board
views still work.

## Trigger and data flow

| Trigger | What it does |
|---|---|
| Cron `0 * * * *` (production only) | Every hour, `src/schedule.ts` reads the Pacific wall clock and sends each digest whose schedule matches |
| `POST /digests/run?key=<key>[&date=YYYY-MM-DD]` | Operator route, `Authorization: Bearer <DIGESTS_SECRET>`. Sends one digest now, even an empty one. `date` sets the digest's date windows |

Flow for one digest:

1. Find the board's columns by title, then read the matching items, using the same rules as the
   board view the email links to.
2. For `recent-gifts`, read each donor's Lifetime Giving and Donor Level from the Donor item.
3. Look up each recipient's email from their Monday user id. Skip deactivated users (warning).
   Refuse any address outside `recipientDomains` (logged as an error, by id). A digest with no
   recipient left fails.
4. Render the branded email. Tables stop at 150 rows and link to the board view (or the board, if
   the view doesn't exist).
5. Send.

Each digest runs on its own; one failure doesn't stop the others. There is no queue, D1 or cursor.
A missed hour is not caught up.

| Digest key | Board view linked | When (Pacific) | Notes |
|---|---|---|---|
| `unmatched-gifts` | Donations › Needs a donor | Mondays 13:00, only when not empty | Gifts with no Donor and not Anonymous Donor |
| `renewals` | People › Renewals this month and next | 1st and 15th, 09:00 | Member Until from the 1st of this month to the end of next month |
| `recent-gifts` | Donations › Gifts, last 60 days | Mondays 08:00 | Received gifts of $400 and up, largest first; no wealth-screening data |
| `fiscal-year-by-size` | Donations › By gift size | Mondays 08:00 | Counts and totals by Gift Size; no item cap |
| `last-week` | Donations › Gifts, last 7 days | Mondays 08:00 | Every gift in the last 7 days, with Status |

List digests refuse a filter that matches more than 5,000 items. Date windows end today.

## Monday boards and columns

Board ids live in `config/svbc.json` (production) and `config/sandbox.json`. Read only. Columns
are found by **title** (through `bareTitle`, so 🔒 markers don't matter), not by id
(`src/digests.ts`).

| Board | Columns read |
|---|---|
| Donations | Donor, Amount, Date, Gift Type, Funding Stream, Gift Size, Status, Anonymous Donor |
| People | Personal Email, Phone, Membership Status, Membership Tier, Member Until; Lifetime Giving and Donor Level (from each gift's Donor) |
| Users | Recipient email addresses, by user id |

A renamed or missing column fails the digest. A donor on Organizations shows blank giving columns.

The board views are created by `salesforce-import`'s `configure` step (`src/configure/spec.ts`) and
found by name (`digests.<key>.view`). A renamed view only breaks the link.

Recipients are Monday user ids in config (`digests.<key>.recipients`), so no staff address is in
this public repo. Who each id is belongs in the private appendix.

## Secrets

| Name | Purpose | Issued by | Rotate |
|---|---|---|---|
| `DIGESTS_SECRET` | Bearer secret for `POST /digests/run` | Generated by the operator (any random string) | `wrangler secret put DIGESTS_SECRET` (`--env sandbox` for sandbox) |
| `MONDAY_API_TOKEN` (optional) | Fallback Monday token from the OAuth cutover; the binding is preferred | Monday (SVBC Integration user) | Delete once the binding is confirmed. Don't add new uses |

`SANDBOX_EMAIL_SINK` is a plain var on the sandbox, and the sandbox Worker refuses to run without
it. See [accounts and access](../03-accounts-and-access.md).

## Write switch

Key `report-digests:writes`. The only sink is email; Monday is only read.

| Mode | Behavior |
|---|---|
| `on` | Sends. |
| `off` (also a missing key) | Builds each due digest and logs one `"writeSwitch":"skipped"` line (`sink: Email`). The operator route answers with the result plus `"writeSwitch": "dry-run"`. |
| `hold` / `unknown` | The cron skips the hour with one `report-digests scheduled: write mode is …` line. The operator route answers 503. **Nothing is caught up.** |

After a hold, resend each digest that fell due with the operator route, `date=` set to the day it
was due. `report-digests:log` = `debug` adds the would-be email to the skip line (addresses masked,
bodies as length only). See [Operations](../07-operations.md).

## Failure modes

| Symptom | Cause | What to do |
|---|---|---|
| Workers Issues error for one digest | Missing or renamed column, Monday error or send error; logged with `console.error` | Read the error, fix the column or config, resend with the operator route |
| A staff member stopped getting a digest | Their Monday user was deactivated (warning), or their address is outside `recipientDomains` (error) | Update `digests.<key>.recipients` in config and deploy |
| Digest fails with no recipients | Every recipient was skipped | Same as above |
| Digest missed after a hold or outage | No catch-up by design | Resend with `date=` |
| Link goes to the board, not the view | View missing or renamed | Recreate it with `salesforce-import`'s `configure`, or match the name in config |
| List digest refuses to run | Filter matched more than 5,000 items | Narrow the digest's rules |
| Sandbox sends fail with "permanent delivery failure" | Sandbox sink mailbox rejecting mail | Check the mailbox still exists before relying on sandbox email |
| Operator route 401 | Wrong or missing bearer secret | Use the current `DIGESTS_SECRET` |
| Operator route 503 | Switch is `hold` or unreadable | Set writes `on` |

The sandbox mailbox accepts mail: a test email to it, sent with `wrangler email sending send`, arrived
on 2026-11-24. Sandbox sends from this Worker were rejected on 2026-10-26; a digest send hasn't been
retried as part of #45.

Production's `EMAIL` binding has no platform destination allowlist, because that would list staff
addresses in the repo. `recipientDomains` is the guard; don't remove it.

## Operator scripts

No scripts. Operator actions:

```sh
# Send one digest now (also for catching up after a hold)
curl -X POST -H "Authorization: Bearer $DIGESTS_SECRET" \
  "https://svbc-report-digests.svbc-account.workers.dev/digests/run?key=last-week"

# Write switch, from the repo root
node scripts/flags.mjs report-digests writes on --env production
```

## Changing it

Key files:

- `src/digests.ts`: what each digest queries and shows, and the column titles it reads.
- `src/schedule.ts`: Pacific schedule matching.
- `src/run.ts`: recipients, domain check, send.
- `src/render.ts`, `src/email/layout.ts`: email HTML. `layout.ts` is a copy; the root README's
  "Branded email template" names the source of truth.
- `src/email/sandboxBinding.ts`: sandbox recipient rewrite.
- `config/*.json`: schedules (`{ "weekdays": [1], "hour": 8 }` with 0 = Sunday, or
  `{ "monthDays": [1, 15], "hour": 9 }`), recipients, views, `skipWhenEmpty`, `days`, `minAmount`.

To add a digest, add its rules in `src/digests.ts`, its config block in both config files, and its
board view in `salesforce-import`'s `configure` spec, so the email and the view agree.

Gotchas:

- `src/flags.ts` and `src/monday/graphql.ts` are byte-identical copies; edit the canonical files
  (see [Development](../05-development.md)).
- `src/digests.ts` imports `scripts/lib/column-titles.mjs` from the repo root.

Test and deploy from `report-digests/`:

```sh
npm test
npm run typecheck
npm run deploy
npm run deploy:sandbox
```

Local dev: `npm run dev:sandbox` with a `MONDAY_API_TOKEN` and `DIGESTS_SECRET` in `.dev.vars` (no
broker locally), then POST to `/digests/run`. See [CI and deploy](../06-ci-and-deploy.md).
