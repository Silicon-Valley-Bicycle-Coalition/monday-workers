# IT Technical Manual Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Markdown IT manual in `docs/manual/`, a generated per-Worker infrastructure appendix,
a CI coverage check, and a pandoc → Chrome PDF build for publishing to Box.

**Architecture:** Three dependency-free `.mjs` scripts with `node:test` tests beside them:
`manual-reference.mjs` (wrangler configs → Markdown tables), `check-manual.mjs` (CI: roster
coverage, template headings, relative links), `build-manual.mjs` (concatenate, rewrite links,
pandoc to HTML, Chrome DevTools `Page.printToPDF`). Hand-written chapters fill the rest.

**Tech Stack:** Node 22.18+ ESM, `node:test`, pandoc (local only), Google Chrome over the DevTools
protocol using Node's built-in `WebSocket`.

**Spec:** `docs/superpowers/specs/2026-11-19-it-manual-design.md`

## Global Constraints

- No new npm dependencies and no root `package.json`; scripts are plain `.mjs` run by Node 22.18+.
- Public repo: name roles, never people, personal emails, phone numbers or secret values.
- Facts that can't be confirmed from the repo or `npx wrangler secret list` are marked
  `**To verify:**` inline and collected in `docs/manual/README.md`.
- Chapter roster = `dir` entries of `.github/workers.json` (deduplicated; `member-portal` once).
- Worker chapters use exactly these nine `##` headings, in order: `What it does`,
  `Trigger and data flow`, `Monday boards and columns`, `Secrets`, `Write switch`,
  `Failure modes`, `Operator scripts`, `Changing it`, `Further reading`.
- Reuse `stripJsonc` from `scripts/check-worker-flags.mjs` and `IN_SCOPE` from the same file;
  don't write a second JSONC parser or write-switch roster.
- GitHub link base: `https://github.com/Silicon-Valley-Bicycle-Coalition/monday-workers`.
- Fonts: data URIs from `member-portal/src/assets/fontData.ts` (`EMBEDDED_FONTS`); never link
  Google Fonts. Colours from `docs/design-system/tokens.json`.
- Generated output (`docs/manual/reference/`, `dist/`) is gitignored.
- No dated deploy status in the manual; link the root README's "Status at a glance".

## Review Focus

1. **A `wrangler.jsonc` with no `env.sandbox`, empty `crons: []`, or `routes` given as strings
   rather than objects** — the reference must render "none"/the string, not crash or print
   `undefined`. Test in Task 1.
2. **A link with an anchor or to a directory** (`../funraise-sync/README.md#deploy`,
   `../scripts/`) — the checker must resolve the path part and accept directories; the PDF build
   must use `blob/` for files and `tree/` for directories and keep the anchor. Tests in Tasks 2, 3.
3. **Links inside fenced code blocks** — not links; neither the checker nor the rewriter may touch
   them. Tests in Tasks 2, 3.
4. **Chrome missing or pandoc missing** — `build-manual.mjs` exits 1 with a one-line message naming
   the tool and `CHROME_PATH`, not a stack trace. Test in Task 3.
5. **A Worker added to `workers.json` without a chapter, or a chapter heading misspelt** — CI
   names the file and the missing heading. Test in Task 2.

### Task 3: PDF build

**Files:**
- Create: `scripts/build-manual.mjs`, `scripts/build-manual.test.mjs`, `docs/manual/print.css`,
  `docs/manual/cover.md` (title, "for SVBC IT", build stamp placeholders `{{date}}`, `{{sha}}`)

**Interfaces:**
- Consumes: Task 1 generator; `EMBEDDED_FONTS` from `member-portal/src/assets/fontData.ts`
  (dynamic `import()` works via type stripping); `docs/design-system/tokens.json`.
- Produces:
  - `CHAPTER_ORDER: { part: string, files: string[] }[]` — Part I `00`–`07`, Part II
    `workers/*.md` sorted, Part III `08`, `09`, then `glossary.md`, Appendix A `reference/*.md`.
  - `rewriteLinks(markdown: string, fromFile: string, opts: { sha: string, manualFiles: Set<string>, isDir: (p) => boolean }): string`
    — repo-relative targets → `<base>/blob|tree/<sha>/<path>[#anchor]`; targets that are manual
    chapters → `#<anchor id of that chapter>`; fenced code untouched.
  - `chapterAnchor(file: string): string` — e.g. `workers/funraise-sync.md` → `ch-workers-funraise-sync`;
    each chapter is wrapped so its first heading gets this id (pandoc `{#id}` attribute).
  - `fontFaceCss(fonts: EmbeddedFont[]): string`; `tokenCss(tokens: object): string` → `:root{--svbc-…}`.
  - `findChrome(env, exists): string | null` — `CHROME_PATH`, then
    `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`, `google-chrome`, `chromium`.
  - `printToPdf(htmlPath: string, pdfPath: string, stamp: string): Promise<void>` — launch Chrome
    `--headless=new --remote-debugging-port=0 --user-data-dir=<tmp>`, read the WS URL from
    stderr `DevTools listening on`, open a target, `Page.navigate` to `file://`, wait for
    `Page.loadEventFired`, `Page.printToPDF` with `displayHeaderFooter: true`,
    `headerTemplate` = manual title, `footerTemplate` = `<span class=pageNumber>` + stamp,
    `generateDocumentOutline: true`, `printBackground: true`, Letter, 0.75 in margins; kill Chrome.
  - CLI: `node scripts/build-manual.mjs [--allow-dirty] [--input <file.md>] [--out dist]`.
    Dirty tree without `--allow-dirty` → exit 1. Missing pandoc/Chrome → exit 1, one line naming
    the tool (and `CHROME_PATH`). `--input` builds a single Markdown file (private appendix) with
    the same styling, no link rewriting to this repo. Output
    `dist/svbc-it-manual-<YYYY-MM-DD>-<shortsha>.pdf`.
  - pandoc: `pandoc -f gfm+attributes -t html5 --standalone --toc --toc-depth=2 --metadata title=…`
    with `--css` inlined via `--embed-resources`.
