# email-log Implementation Plan

> **Superseded 2026-11-04, not built.** Email is logged with Monday CRM Emails & Activities instead; see `docs/superpowers/specs/2026-11-12-organizer-email-logging-design.md`.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new Worker, `email-log`. Staff BCC or forward an email to a Cloudflare Email Routing
address, and it becomes one item on the Activities (Logged) board, linked to the People it
matches.

**Architecture:** An `email()` handler parses the message with `postal-mime`, authenticates
the sender, classifies it (BCC vs forward), drops staff-only mail, claims a dedupe row in D1, and
enqueues the extracted fields. A queue consumer matches addresses to People, adopts or creates
the Activities (Logged) item, marks the D1 row, and replies to the staff member only when
something didn't match or the message dead-lettered. The shape follows `eventbrite-sync`
(queue + DLQ + D1 ledger + sandbox env) and `bp-feedback-notify` (the `send_email` binding and
the sandbox recipient lock).

**Tech Stack:** TypeScript 7, Cloudflare Workers (Email Routing `email()` handler, Queues, D1,
`send_email`), `postal-mime`, vitest + `@cloudflare/vitest-plugin`, the canonical Monday
GraphQL transport.

**Spec:** `docs/superpowers/specs/2026-10-19-email-log-design.md`. Read it first; this plan
doesn't repeat its reasoning.

## Global Constraints

- Directory `email-log/`, Wrangler name `svbc-email-log` / `svbc-email-log-sandbox`, D1
  `svbc-email-log` / `-sandbox`, queues `email-log-writes` (+ `-dlq`), `-sandbox` suffixed in env.sandbox.
- `package.json`, `tsconfig.json`, `vitest.config.ts`, `test/apply-migrations.ts`, `test/jsonc.ts`,
  `test/raw-imports.d.ts` copied from `eventbrite-sync/` and renamed; same dependency versions,
  plus `postal-mime` as the only new runtime dependency (no `hono`: there's no HTTP route).
- `src/monday/graphql.ts` is a byte-identical copy of `monday-backup/src/monday/graphql.ts`; add
  `email-log/src/monday/graphql.ts` to the `monday-graphql-copies` job's list in `.gitlab-ci.yml`.
- `src/environment.ts` copied verbatim from `eventbrite-sync/src/environment.ts`.
- Never `console.*` an email address, subject, or body. Log the first 12 hex chars of
  `messageIdHash` as the correlation id. `node scripts/check-log-safety.mjs` must pass.
- D1 holds no address, subject or body. The queue payload is the only place they exist outside Monday.
- `bodyMaxChars` default 1900; truncated text ends in `… [truncated]`. Monday item names are
  cut to 255 characters.
- Logging address default `log@log.bikesiliconvalley.org`, sandbox `log-sandbox@log.bikesiliconvalley.org`.
  Reply sender is on `mail.bikesiliconvalley.org`.
- Sandbox `send_email` binding: `allowed_destination_addresses: ["sandbox@bikesiliconvalley.org"]`
  plus the code-layer `sandboxEmailBinding` wrapper copied from `bp-feedback-notify/src/email/sandboxBinding.ts`.
- The reply and README wording never suggests BCCing every email: the rule is "significant
  touches only" (spec Decision 2).
- Every new `wrangler.jsonc` env block restates `routes: []` (memory: a new env without explicit
  routes can steal live custom domains); this Worker has no routes at all.
- Run Worker tests with the sandbox disabled (workerd binds a local port).

## Review Focus

1. **Forged `Authentication-Results`.** Anyone can put `Authentication-Results: …; dkim=pass
   header.d=bikesiliconvalley.org` in their own headers. Trust only headers whose authserv-id equals
   config `trustedAuthServId`, and only the topmost such header. Test: Task 3 `ignores a forged
   header below Cloudflare's`.
2. **The logging address or staff in To/Cc** (someone puts `log@` in To instead of BCC, or
   CCs a colleague). Both are excluded from counterparts, and the message is still logged
   against the external recipients. Test: Task 5 `excludes the logging address and staff from counterparts`.
3. **Forward of a message the staff member sent themselves** (forwarded From is staff). The
   counterparts become the forwarded block's To + Cc, minus staff. Test: Task 5 `forward of
   staff's own sent message uses the block's To and Cc`.
4. **No `Message-ID` header.** Some clients and list servers omit it. Fall back to the
   (from, date, subject) hash instead of crashing or colliding on an empty hash. Test: Task 6
   `falls back when Message-ID is missing`.
5. **Long or emoji-heavy subjects and bodies.** Truncation must not split a surrogate pair, and
   names over 255 characters must not fail `create_item`. Test: Task 4 `truncates without
   splitting a surrogate pair` and Task 9 `cuts the item name to 255 characters`.
