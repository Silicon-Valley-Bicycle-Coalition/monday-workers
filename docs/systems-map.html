The shared reliability pattern

Most of the Workers (funraise-sync, eventbrite-sync, quickbooks-sync, benevity-import, donation-rollups, mailchimp-sync, member-portal’s change-request and letter queues, nearby-search) share one shape, added after an outside reviewer found that a bare fetch() to Monday's API has no retry of its own — a rate limit or a transient 5xx just silently drops the write.

What's actually live today

Built does not mean deployed, and sandbox does not mean production. Every migration Worker carries a sandbox Wrangler environment (its own name, D1, queues, secrets, and a config/sandbox.json) and can only email sandbox@bikesiliconvalley.org. Every Worker's sandbox config targets the CRM Sandbox v4 workspace (18210301; the last v3 references were dropped 2026-11-11). Production deploys follow docs/production-deploy-checklist.md; where the repo records a deploy, the row says so, and otherwise it says only what config has been filled.

Write mode. Orthogonal to the state below, each of the thirteen Workers that write has a <worker>:writes mode in a shared Workers KV namespace: on (write), hold (write nothing, keep work queued, queues paused) or off (write nothing, log the dry run; a missing key reads as off). The FLAGS and sandbox-FLAGS namespaces were created 2026-10-27. Set with scripts/flags.mjs; see docs/runbooks/migration-hold.md.
