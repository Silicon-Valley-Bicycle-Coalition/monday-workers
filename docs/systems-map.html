The shared reliability pattern

Six of the Workers above (funraise-sync, eventbrite-sync, quickbooks-sync, benevity-import, donation-rollups, mailchimp-sync) share one shape, added after an outside reviewer found that a bare fetch() to Monday's API has no retry of its own — a rate limit or a transient 5xx just silently drops the write.

What's actually live today

Built does not mean deployed, and sandbox does not mean production. Every migration Worker carries a sandbox Wrangler environment (its own name, D1, queues, secrets, and a config/sandbox.json) that targets the "(sandbox v3)" boards and can only email sandbox@bikesiliconvalley.org. Only svbc-calendars exists in production; the migration Workers' first production deploy is the cutover checklist.

Write mode. Orthogonal to the state below, each of the twelve Workers that write has a <worker>:writes mode in a shared Workers KV namespace: on (write), hold (write nothing, keep work queued, queues paused) or off (write nothing, log the dry run; a missing key reads as off). Built on main but not yet deployed: the KV namespaces are not created, so the ids are placeholders. Set with scripts/flags.mjs; see docs/runbooks/migration-hold.md.
